# 简历与作品集：没有实习经历怎么写

> 一句话概括：没有实习不等于没有素材——课程项目、竞赛、自学、开源，都能写成有效经历。

**适用人群**：大二大三想找第一份实习的人；秋招时简历上一片空白的人；跨专业求职的人。

> **政策适用范围**
> - 主要依据：无政策法规——本文是求职方法与写作技巧
> - 全国统一 / 地方执行：不适用
> - 核查日期：2026-11-05
> - 相关法律边界：简历内容不得编造（涉及《劳动合同法》第八条如实说明义务、第二十六条合同无效），详见 09-04

> ⏳ 本文的方法长期有效，但**招聘平台的具体功能、工具名称会变**。

---

## 一、先解决一个心理问题

「没有实习经历」是大学生最普遍的焦虑，但它的实质不是「你没有经历」，而是**「你不知道哪些东西算经历」**。

招聘方看简历，真正想判断的是三件事：

| 想判断 | 靠什么证据 |
| --- | --- |
| 你能不能做这件事 | 做过的类似任务、作品、项目 |
| 你会不会学 | 自学轨迹、跨领域完成的事 |
| 你靠不靠谱 | 持续投入过的事、团队中的角色 |

**实习只是证据之一，不是唯一证据。** 一段做得深的课程项目，比一段只是「打杂」的实习更有说服力。

## 二、四类可以写的素材（按说服力排序）

### 2.1 课程项目 / 大作业

**为什么有效**：有真实的问题、真实的过程、真实的结果，且能被追问。

**关键：不要写「完成了 XX 课程设计」，要写你解决了什么。**

| 差写法 | 好写法 |
| --- | --- |
| 完成了数据库课程设计 | 设计并实现一个 X 张表的图书借阅系统，用索引优化把主要查询从全表扫描改为索引扫描，QPS 从 X 提升到 Y |
| 参加过机器学习课程 | 在 XX 数据集上复现 XX 模型，通过调整 XX 将准确率从 A% 提升到 B%，并分析了提升来源 |

> 数字必须真实。**能说清口径的数字才是有效数字**（见 09-04）。

### 2.2 竞赛

**为什么有效**：有排名、有对手、有明确评价标准，是最硬的第三方证据。

| 竞赛类型 | 怎么写 |
| --- | --- |
| 有排名的 | 写明赛事全称、级别、名次/奖项、参赛人数或队伍数 |
| 无排名但入选 | 写明「入选」「入围」的具体层级 |
| 团队赛 | **必须写清你负责哪部分**，否则会被当成队友的功劳 |

**注意**：竞赛名称要写**全称**。缩写在跨校、跨行业的读者眼里等于没写。

### 2.3 自学成果

**为什么有效**：证明学习能力和自驱力，这是校招最看重的东西之一。

**怎么让它可信**——必须留下**可验证的痕迹**：

| 素材 | 可验证形式 |
| --- | --- |
| 自学某技术栈 | 有可运行的成品 / 有代码仓库 |
| 读过的书与笔记 | 有公开笔记、有总结文章 |
| 跟完的课程 | 有证书（写清颁发机构与课程全称） |
| 复现论文 | 有仓库 + 复现结果对比 |

**不要写「自学能力强」这句空话**，写你自学了什么、做出了什么。

### 2.4 开源 / 作品集

**为什么有效**：完全公开可查，是**最难造假**的证据，对技术岗尤其有效。

| 形式 | 说明 |
| --- | --- |
| 给开源项目提 PR | 写明项目名、PR 编号、你改了什么 |
| 自己的仓库 | 有 README、有可运行说明、有 commit 历史 |
| 设计/写作作品 | 作品链接、发布平台、阅读/使用数据 |
| 博客 | 持续更新比数量多更重要 |

**一个真实的小仓库，胜过十个只建了空壳的仓库。**

## 三、STAR 式改写：把「做过」变成「能证明能力」

STAR 是 Situation（情境）、Task（任务）、Action（行动）、Result（结果）。

### 3.1 简历里用 STAR 的压缩版（一两行）

简历空间有限，不需要写全 STAR，但要有这四要素的**痕迹**。

**模板**：

> 【情境+任务】为了做 XX，【行动】我用了 XX 方法做了 XX，【结果】最终达到 XX。

**示例一（课程项目）**

原句：
> 做过一个校园二手交易平台。

改写：
> 为解决班级二手教材流转靠微信群刷屏的问题，独立开发一个交易小程序（前端 XX + 后端 XX），上线后覆盖本班及两个兄弟班级，累计成交 XX 单；针对商品重复发布问题，设计了基于标题相似度的去重规则。

**示例二（竞赛）**

原句：
> 参加过数学建模比赛，获得省级奖项。

改写：
> 在全国大学生数学建模竞赛中负责建模与编程（队伍 3 人），针对 XX 类问题建立 XX 模型，用 XX 方法求解，完成 XX 页论文；获省级 XX 等奖。

**示例三（自学）**

原句：
> 自学了 Python 和数据分析。

改写：
> 用 3 个月系统学习 Python 数据分析，完成 X 个练习项目；将某公开数据集的清洗与可视化流程整理成可复用脚本，发布在个人仓库（附链接）。

### 3.2 改写的四条纪律

| 纪律 | 说明 |
| --- | --- |
| 用动词开头 | 「设计」「实现」「优化」「搭建」，不用「参与了」 |
| 有具体对象 | 「XX 系统」「XX 数据集」，不写「一些项目」 |
| 有可验证结果 | 数字、上线、使用人数、排名、链接 |
| 能被追问 | 每个技术选择你都要能说清「为什么这么选」 |

**第 4 条最容易被忽略。** 面试官会顺着简历往下问，写上去的每个词都要能接住三轮追问。写不动的就不写。

## 四、常见经历的说法对照

| 你的实际情况 | 不要这么写 | 可以这么写 |
| --- | --- | --- |
| 只在课上跟着做过实验 | 「熟练掌握 XX 技术」 | 「完成 X 个 XX 实验，独立实现了 XX 部分」 |
| 参加过社团但没做技术 | 「担任干事」 | 「负责 X 人活动的 XX 环节，协调 X 个部门，完成 XX」 |
| 做过家教/兼职 | 「做过兼职」 | 「一对一辅导 X 名学生 XX 科目，X 个月内平均分提升 X 分」 |
| 帮老师做过杂活 | 「协助老师科研」 | 「协助整理 X 份 XX 数据，编写脚本将手工处理时间从 X 缩短到 Y」 |
| 参加过比赛没获奖 | 不写 | 可写「参赛并完成 XX 作品」（真实即可） |
| 只有课设 | 「无实习经历」留白 | 把课设写详细，占满教育/项目栏 |

## 五、简历的结构、排版与按岗位改写

### 5.1 一页纸原则

应届生简历**一页**足够。写不满说明素材没挖出来，写超了说明不会取舍。

### 5.2 板块顺序（无实习版）

| 顺序 | 板块 | 说明 |
| --- | --- | --- |
| 1 | 基本信息 | 姓名、联系方式、邮箱、求职意向 |
| 2 | 教育背景 | 学校、专业、学历、时间、GPA/排名（好才写） |
| 3 | **项目经历** | **无实习时这是主体，放在最靠前的位置** |
| 4 | 竞赛/获奖 | 有则写，写全称与层级 |
| 5 | 技能 | 具体到工具与熟练程度，别写「精通 Office」 |
| 6 | 其他 | 开源、作品集链接、证书、社团 |

### 5.3 排版红线

- [ ] 不用花哨模板，**纯黑白、单栏**最稳
- [ ] 不用彩色分栏（很多 ATS 系统解析会乱）
- [ ] 文件名：`姓名-岗位-学校.pdf`
- [ ] 格式：**PDF**，不要发 Word（排版会崩）
- [ ] 字体统一，层级不超过三级
- [ ] 不留错别字（这是最直接的能力信号）

### 5.4 关于「简历筛选系统」

很多公司用系统自动解析简历。为降低解析失败：

- 不用表格嵌套、不用文本框、不用图片承载文字
- 联系方式放在页面顶部正文里，不要放在页眉
- 用标准板块名（教育背景、项目经历、技能）

### 5.5 按岗位改写

同一段经历，投不同岗位要突出不同侧面。这是投递效率的关键。

| 目标岗位 | 突出什么 |
| --- | --- |
| 后端开发 | 数据结构、并发、数据库设计、接口设计 |
| 前端开发 | 交互实现、性能优化、组件设计 |
| 数据分析 | 数据清洗、指标设计、结论落地 |
| 算法 | 模型选择理由、实验设计、指标对比 |
| 产品 | 需求来源、方案取舍、数据验证 |
| 运营 | 目标、手段、可量化结果 |

**做法**：为每个目标岗位存一版简历。**不要用同一份简历投所有岗位**——这是投递无效的最常见原因。

## 六、作品集与不要做的事

### 6.1 作品集怎么做

| 岗位方向 | 作品集形态 | 关键点 |
| --- | --- | --- |
| 开发 | 代码仓库 + 可访问的 demo | README 写清怎么跑、做了什么 |
| 设计 | 作品集 PDF / 在线站点 | 每件作品写清**设计目标与取舍**，不只放图 |
| 写作/内容 | 发表链接合集 | 标注平台、时间、数据 |
| 数据 | Notebook / 报告 | 问题—方法—结论完整 |
| 研究 | 论文/报告 | 你的贡献要写清 |

**作品集的一条铁律**：每个作品都要有「为什么」——为什么做、为什么这样设计、遇到什么困难、怎么解决。只有成品的作品集，说服力约等于没有。

### 6.2 不要做的事

| 不要 | 原因 |
| --- | --- |
| 编造实习经历 | 背调可查社保与在职记录（详见 09-04） |
| 把课程作业写成「公司项目」 | 一问细节就崩 |
| 把团队成果写成个人主导 | 面试官会问你的具体分工 |
| 写「精通」但不敢被追问 | 一次深挖就暴露，反而扣分 |
| 罗列一堆技能名词 | 无法证明等于没有 |
| 用同一份简历海投 | 匹配度低，通过率极低 |
| 简历里放无关照片与个人信息 | 增加被歧视风险，无收益 |

## 常见误区

| 误区 | 实际 |
| --- | --- |
| 「没实习就没法写简历」 | 项目、竞赛、自学、开源都是有效素材 |
| 「课程项目太水，不值得写」 | 写得具体就有说服力；空泛才水 |
| 「简历越长越显得经历丰富」 | 应届生一页足够，多了是减分 |
| 「写得夸张一点没关系」 | 编造属欺诈，可能导致合同无效且无补偿 |
| 「技能写得越多越好」 | 写上去的都要能被追问 |
| 「简历发 Word 方便对方改」 | 排版会崩，一律发 PDF |
| 「一份简历投所有岗位」 | 应按岗位改写关键词与侧重点 |

## 可执行清单

**素材盘点（先做这一步）**

- [ ] 列出所有课程项目，每个写清：解决什么问题、你做了什么、结果如何
- [ ] 列出所有竞赛：全称、级别、名次、你的分工
- [ ] 列出所有自学成果：学了什么、做出了什么、有无可验证痕迹
- [ ] 列出所有开源贡献与作品链接
- [ ] 列出兼职、社团、志愿经历中的可量化部分

**写作**

- [ ] 每条经历都用「情境+任务+行动+结果」检查一遍
- [ ] 动词开头，去掉「参与」「协助」这类弱动词
- [ ] 每个数字都能说清统计口径
- [ ] 每个技术选择都能回答「为什么」
- [ ] 删掉所有无法被追问的形容词

**排版**

- [ ] 一页纸
- [ ] 单栏、黑白、无文本框
- [ ] 无错别字（朗读一遍）
- [ ] 导出 PDF，文件名 `姓名-岗位-学校.pdf`
- [ ] 在手机上打开看一眼（很多 HR 手机看简历）

**投递**

- [ ] 按目标岗位准备 2–3 个版本
- [ ] 每版对照 JD 检查关键词覆盖
- [ ] 作品集链接确认可访问（不要有登录墙）

## 一句话记住

**没有实习不是空白，是没挖——把课程项目、竞赛、自学、开源按「问题—行动—结果」写清楚，比一段打杂实习有用得多。**

1. 【经验】STAR 法则为求职领域的通用表达框架，非官方规范。
