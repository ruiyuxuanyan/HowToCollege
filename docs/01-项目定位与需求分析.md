# 项目定位与需求分析

> 本文是第一阶段规划文档之一。核查日期：2026-11-04。

## 一、项目定位

**「大学生生活指南」是一份发布在 GitHub 上的开放式知识库，载体是 Markdown 文档。**

不做 App / 小程序 / 账号 / 后端；在线站是同一份 Markdown 的静态渲染视图，由 CI 自动重建。**内容只有 Markdown 这一个源，站点不是另一个版本，也不需要单独维护。**

它和现有资源的关系，用一句话说清：

| 现有资源 | 它解决什么 | 它没解决什么 |
| --- | --- | --- |
| 学校发的《新生手册》 | 校规、地图、报到流程 | 校外的事一件都不讲 |
| 「Survive 某某大学」系列 | 校内生存技巧、保研出国经验 | 高度依赖本校、依赖作者个人经验、无出处 |
| 知乎/小红书帖子 | 真实体验、细节丰富 | 无法核验、真假混杂、随时消失 |
| 政策官网 | 权威、准确 | 分散在几十个部门网站，学生不知道去哪查、看不懂 |

本项目补的是这个缺口：**把散落在政策文件、官方办事指南和学生真实经验里的信息，整理成"看完就能照着做"的条目，并标明每条信息的可信度和失效风险。**

### 不属于本项目的事

明确划出边界，避免项目变形：

- 不做 App、不做小程序、不做账号体系、不做后端服务（不做需要登录、需要服务器、需要持续运维的东西）
- 不做考研/考公/留学的备考资料库（那是另一个赛道，已有充分供给）
- 不做课程辅导、不做答案共享
- 不做高校排名、不做择校推荐（已有 [CollegesChat/university-information](https://github.com/CollegesChat/university-information) 这类项目）
- 不替读者做决定，只把选项的代价讲清楚

### 为什么不做 App / 小程序 / 账号 / 后端

参考项目 HowToLiveBetter 已经证明纯 Markdown 可行，而且有明确好处：

1. **GitHub 直接渲染**，读正文不需要任何部署，也不用维护服务器
2. **任何人都能通过 PR 修正内容**，不需要懂代码
3. **fork 即备份**，不会因为作者停更而消失
4. **diff 可查**，每条内容的每次修改都有记录

**在线站也在做，但只做静态渲染。** `site/index.html` 是手写的静态壳，`tools/build-site.mjs` 把同一份 Markdown 打成 JSON 供前端读取，CI 每次推送自动重建。这个层面的成本是可接受的：它是**构建产物，不是第二个内容源**——改内容只改 Markdown 一处，站点跟着自动变，没有「两边要同步」的问题。

反过来，一旦做成 App / 小程序 / 需要账号和后端的产品，维护成本会从「写内容」变成「写内容 + 修 bug + 续服务器 + 防被墙 + 管用户数据 + 应对合规」,这是绝大多数同类项目死掉的原因。

## 二、用户需求分析

### 2.1 用户画像

本项目面向中国大陆的在校与准在校学生，按阶段分为五类：

| 用户类型 | 典型时间点 | 最紧迫的需求 |
| --- | --- | --- |
| 准大学生 | 高考出分后到入学前 | 报到要带什么、怎么防录取诈骗、学费怎么交、要不要迁户口 |
| 大一新生 | 入学第 1 个月 | 选课怎么选、军训怎么熬、宿舍关系、社团要不要加、钱怎么管 |
| 在校中年级 | 大二到大三 | 兼职不踩坑、奖学金与助学贷款、实习怎么找、考证值不值、情绪问题 |
| 高年级 | 大三下到大四 | 秋招春招、三方协议怎么签、保研考研抉择、租房、毕业手续 |
| 应届与毕业 2 年内 | 毕业后 | 档案户口、劳动合同、五险一金、试用期、被辞退、租房维权 |

### 2.2 需求的三个来源

**来源一：信息不对称。** 学生踩坑往往不是因为笨，而是因为「从来没人告诉过他还有这回事」。典型例子：

- 不知道兼职被欠薪时，劳动监察不管（因为不构成劳动关系），要走的是法院起诉或检察支持起诉
- 不知道三方协议违约要付违约金，签之前以为是意向书
- 不知道应届生身份在部分省份已放宽到毕业 2 年内，白白放弃了择业期
- 不知道助学贷款在校期间利息由国家贴息

这类问题的共同特征是：**不知道就一定会吃亏，而且吃亏时还不知道自己吃了亏。**

**来源二：决策成本高。** 有些事学生知道要做，但无从下手。比如第一次租房、第一次签劳动合同、第一次自己交医保。信息散落在多个平台，凑齐一次很费力。

**来源三：风险规避。** 涉及钱、法律、人身安全的事，一旦出错代价远大于其他生活琐事。这类内容哪怕只有少数人看，价值也最高。

### 2.3 需求优先级判断方法

每个选题按四个维度打分（详见 `02-内容选题清单.md`）：

| 维度 | 含义 | 权重 |
| --- | --- | --- |
| 覆盖面 | 有多少比例的学生会遇到 | 高 |
| 损失量级 | 踩坑的代价（钱、时间、法律后果、健康） | 高 |
| 信息可得性 | 现在能不能轻松查到可靠答案（越难查越值得写） | 中 |
| 时效稳定性 | 内容多久会过时（越稳定越适合先写） | 中 |

**计算方式**：

- 「覆盖面 × 损失量级」= 核心价值，决定是否入选
- 「信息可得性」反向计分：网上已经铺天盖地讲清楚的，优先级降低
- 「时效稳定性」影响写法：易过时的内容必须写明核查日期和政策适用范围

### 2.4 明确不服务的需求

- **解决感情纠纷的具体建议**：不介入具体个案，只讲通用规则（如恋爱期间大额转账的法律定性）
- **代写简历/代做作品集**：提供方法论和自查清单，不代做
- **心理疾病诊断**：只提供「什么情况该去就医、去哪就医、怎么求助」，不做诊断
- **考试技巧与押题**：不属于生活指南范围

## 三、与参考项目的对比

参考项目 [HowToLiveBetter](https://github.com/eternity4719/HowToLiveBetter) 的结构值得学习，但它的内容基座是「终身人生决策」，本项目是「大学这个特定阶段的密集决策」。

### 3.1 值得照搬的

1. **单条建议作为最小可读单元**：读者不需要通读全书，搜到一条就能用
2. **成本/收益/证据分级的固定字段**：让「值不值得做」变得可比
3. **证据等级与性价比分开**：「数字可不可信」和「这事值不值得做」是两个问题
4. **纯 Markdown + 静态检索页**：检索页是 Markdown 的渲染视图，零服务器成本（本项目已实现，见 `site/`）
5. **内置 AI skill**：让 AI 查书回答，而不是自由发挥（第二阶段再考虑，第一阶段不做）

### 3.2 必须调整的

| 参考项目做法 | 本项目为什么不能照搬 |
| --- | --- |
| 每条给 A/B/C 证据等级（有 RCT 或大样本队列才给 A） | 大学生生活问题绝大多数没有随机对照试验。硬套会逼着写作者编数字。改为「信息来源等级」 |
| 以期刊论文和 DOI 为主要来源 | 本项目的一手来源是政策文件、法律条文、官方办事指南，期刊论文只在健康类选题使用 |
| 收益量化成「死亡率降低 12%」 | 大学生问题更多是「省多少钱」「少跑几趟」「避免什么后果」，量化方式不同 |
| 全书 772 条统一体例 | 本项目按主题分文档，每篇长文自带结构，不强求逐条对齐 |
| 面向全年龄 | 本项目的政策内容必须写明地区与学年适用范围 |

### 3.3 本项目独创的设计

**1. 三级来源标注。** 每个关键结论标注来源类型，读者一眼能看出该不该信：

| 标记 | 含义 | 例子 |
| --- | --- | --- |
| 【法规】 | 法律、行政法规、部门规章原文 | 《劳动合同法》第十九条 |
| 【官方】 | 政府部门、高校官网发布的办事指南、政策解读 | 教育部全国学生资助管理中心公告 |
| 【经验】 | 学生或从业者的个人经历、社区讨论 | 知乎回答、贴吧帖、访谈 |
| 【待核实】 | 找到了说法但没有可靠来源，或来源之间冲突 | 各校执行口径不一、政策刚变动 |

**这是本项目最重要的设计。** 大学生内容最大的坑，就是把「某校规定」说成「全国规定」、把「某个学长说」说成「普遍事实」。三级标注强制写作者区分这三件事。

**2. 政策适用性声明。** 涉及政策、补贴、报销、办事流程的文章，必须在开头标明：

- 依据的政策文件名与文号
- 该政策是**全国统一**还是**地方执行**（地方执行的，说明差异来源）
- 核查日期
- 已知即将变化的事项

**3. 失效风险标记。** 有些内容天然会烂（补贴金额、办事流程、App 界面）。这类内容标注「⏳ 易过时」，并在 CHANGELOG 里登记复查时间。

## 四、第一阶段结论

1. 项目定位：面向中国大陆大学生的循证式生活知识库，**内容是纯 Markdown 单一源**；在线站是它的静态渲染视图，由 CI 自动重建，不做 App / 小程序 / 账号 / 后端
2. 核心差异化：三级来源标注 + 政策适用性声明 + 失效风险标记
3. 内容策略：优先写「高频 × 高损失 × 难查得到」的选题
4. 首批交付：见 `02-内容选题清单.md` 与 `03-首批20篇写作顺序.md`
